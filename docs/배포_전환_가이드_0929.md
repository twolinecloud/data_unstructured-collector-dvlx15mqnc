## 1. 배포 — Jenkins

1. Jenkins 에서 `unstructured-collector-dvlx15mqnc` 잡을 **브랜치 `dev`** 로 실행한다.
2. 끝나면 `data_HelmChart` master 에 `Pushed Helm Chart: …-unstructured-collector-dvlx15mqnc-<sha>` 커밋이 올라오고
   ArgoCD 가 동기화한다. 태그의 `<sha>` 가 이 저장소 dev 의 최신 커밋과 같은지 본다.

## 2. 배포 확인 — 전환 전에

## 3. 전환 — admin-fe `/voice/` → unstructured-collector

2번이 모두 맞으면:

```bash
cd service_admin-fe-iqgor1oiru
git fetch origin
git checkout dev && git pull --ff-only origin dev
git merge --no-ff origin/feature/unstructured-cutover -m "Merge branch 'feature/unstructured-cutover' into dev — /voice/ → unstructured-collector"
git push origin dev
git checkout feature/deid-demo
```

- 바뀌는 것은 `custom-nginx.conf` 의 `set $voice_backend …` 한 줄(과 주석)뿐이다.
- nginx 설정은 **이미지 빌드 때 들어간다**(Dockerfile `COPY custom-nginx.conf`) → admin-fe Jenkins 를 dev 로 다시 빌드해야 반영된다.
- 확인: admin-fe 의 시뮬레이터 6번 탭 머리에 `Admin DB 연결 · 매핑 테이블 있음` 이 뜨면 새 서비스를 보고 있는 것이다
  (옛 서비스를 보고 있으면 `이미지 API 없음`).

### 되돌리기

옛 서비스가 그대로 떠 있으므로 머지 커밋을 되돌리고 admin-fe 를 다시 빌드하면 된다.

```bash
git checkout dev && git revert -m 1 <머지 커밋> && git push origin dev
```

## 4. 전환 뒤 정리

### 4-1. 데이터 저장소 독립 (2026-09-30 완료)

전환 직후에는 unstructured-collector 와 브로커가 **옛 voice-collector 차트 소유의 PVC**(`pvc-voice-collector-x2daarjxe4`)를
함께 붙이고 있었다 — 옛 서비스를 지우면 그 PVC 와 함께 둘 다 깨지는 구조. 이렇게 끊었다.

1. 새 RWX PVC `pvc-unstructured-collector-data`(25Gi, `nfs-client`, 보존 표시) · RVS 키 `unstructured-collector-rvs-key` 를 먼저 만들었다
2. 데이터 복사 — 옛 공유 PVC 의 `k8s`(성능 이력 · 상태 3개)와 새 서비스 자기 PVC 의 `k8s`(전환 뒤 쓴 것 116개 — 6번 탭 SIM 사진 50 ·
   SIM 원본 65 · `image-history.jsonl`)를 합쳐 옮기고 파일 해시로 대조했다(119개 일치)
3. 차트(`164f8e2` → master `923334a`) — 수집기 차트가 새 PVC 를 만들고, 수집기·브로커의 `sharedClaim` 을 새 PVC 로. 두 앱을 연달아 동기화
4. 검증 — 브로커 추출 API 가 새 PVC 에 쓴 파일이 수집기 수신 폴더에 2초 만에 보임 · 6번 탭 재실행 50건 정합성 ✓(새 키로 복호화 50/50)

> 참고: 새 서비스 자기 PVC(`pvc-unstructured-collector-dvlx15mqnc`)의 `k8s/` 폴더는 복사 원본으로 남아 있다(지금은 아무도 안 쓴다).
> 이 PVC 는 `/logs` 용으로 계속 쓴다.

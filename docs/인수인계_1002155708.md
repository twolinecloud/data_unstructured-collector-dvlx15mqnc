### 1.4 장애 시나리오 — 키 표식 · 실제 경로에서 **한 번만** 실패 (`mock/FailureScenario` · `mock/ScenarioFaults`)

| 시나리오 | 표식 | 음성 실패 단계 | 어디서 실패시키나(개발계 모드 기준) | 기대 재처리 | 이미지 |
|---|---|---|---|---|---|
| COLLECT_FAIL | `CF` | COLLECT | 접견: **수집기가 브로커 추출 요청 직전**에 끊음 · 전화: **Mock 전화 제공자**가 거부 | `FULL` | ACQUIRE(브로커 수신 직전) |
| ANALYZE_FAIL | `AF` | ANALYZE | **Mock STT** 가 HTTP 500 처럼 실패 → 복호화 오디오 보존 | `FROM_ANALYZE` | DECRYPT(복호화 직후 — 이미지 확인 실패) |
| SEND_FAIL | `SF` | SEND | **제논 MOCK** 이 HTTP 503 처럼 거부 → 전사 보존(`stt_temp`) · REST 면 `tools/zenon-mock` 서버가 같은 표식에 503 | `FROM_SEND` | MAP(Admin DB 매핑 — 커밋 전 롤백) |

**왜 키 표식 + 1회인가**
- 개발계 접견은 브로커(REST · DUMMY 어댑터)가 **FILEKEY 가 없거나 읽히지 않아도 무음 WAV 를 만들어 준다**(브로커 `DummyXvarmAdapter` 확인) — "파일 안 만들기" · "FILEKEY 누락" 만으로는 실패하지 않는다. 브로커는 다른 저장소라 손대지 않고 수집기 쪽에서 끊었다(5장 #10).
- 손상 파일로 ANALYZE 를 노리면 이 코드에서는 **복호화 실패 = COLLECT** 로 집계되고, Mock STT 는 내용을 보지 않는다 — Mock STT 에 키 표식 실패를 넣었다(작업 지시 2-3 의 "안 되면 Mock 에 추가").
- 데이터 성질로 실패시키면 재처리도 똑같이 실패한다. 처음 닿을 때만 실패시키고 **소진 표시**를 남겨 재처리는 통과한다.
- 판정은 **형식이 정확히 맞는 키만**(`^(SIM|DMY)-(MEET|PHONE)-\d{8}-(CF|AF|SF)-\d{4}$` · `^(SIM|DMY)IMG\d{10}(CF|AF|SF)$`). 실제 키 · 기존 시연 키는 어떤 경우에도 걸리지 않는다.
- **운영 프로필에서는 아무 일도 하지 않는다**(`ScenarioFaults` 가 prod 면 비활성 — 테스트로 고정).

**한계**: 소진 표시는 프로세스 메모리다. 실패와 재처리 사이에 파드가 다시 뜨면 재처리에서 한 번 더 실패하고 그다음이 성공한다(5장 #2). 더미 초기화가 그 용도의 소진 표시를 지운다.

**시나리오별 구간**: 유형마다 건수가 같고 순서가 `[CF… → AF… → SF… → 정상…]` 이라 시나리오마다 `CRT_DT` 구간이 겹치지 않는다(응답 `windows`).
그 구간을 기대 모드로 재처리하면 그 시나리오 건만 다시 돈다. `POST /api/v1/voice/batches/resume` 에 **`from` · `to` 파라미터를 추가**했다(주면 `lookbackMin` 무시).

### 1.5 시나리오별 재현 방법

```bash
# 1) 생성 — 시뮬레이터(SIM) 기준. 대시보드면 target=DASHBOARD, test=false
curl -s -X POST localhost:18095/api/v1/mock/sim-data/generate -H 'Content-Type: application/json' \
  -d '{"target":"SIMULATOR","dataTypes":["MEET","PHONE","IMAGE"],"count":5,"failures":{"COLLECT_FAIL":1,"ANALYZE_FAIL":1,"SEND_FAIL":1}}'
# 2) 1차 실행 — 대상일 하루(응답 targetDate). 표식 건이 COLLECT · ANALYZE · SEND 에서 FAIL
curl -s -X POST 'localhost:18095/api/v1/voice/batches/manual?from=2026-10-01T00:00:00&to=2026-10-02T00:00:00&test=true'
curl -s -X POST localhost:18095/api/v1/image/batches -H 'Content-Type: application/json' -d '{"corrNoPrefix":"SIMIMG"}'
# 3) 재처리 — 응답 windows 의 시나리오 구간 · 기대 모드
curl -s -X POST 'localhost:18095/api/v1/voice/batches/resume?resume=FULL&from=<windows.COLLECT_FAIL.from>&to=<…to>&test=true'
curl -s -X POST 'localhost:18095/api/v1/voice/batches/resume?resume=FROM_ANALYZE&from=<windows.ANALYZE_FAIL.from>&to=<…to>&test=true'
curl -s -X POST 'localhost:18095/api/v1/voice/batches/resume?resume=FROM_SEND&from=<windows.SEND_FAIL.from>&to=<…to>&test=true'
curl -s -X POST localhost:18095/api/v1/image/batches -H 'Content-Type: application/json' -d '{"corrNoPrefix":"SIMIMG"}'   # 실패 건만 다시
```

- 화면: 3번 탭 **⑤ 키 표식 장애 시나리오** [🚀 원클릭] 이 위 1~3 을 하고 건별로 "1차에 기대 단계에서 실패 ✔ · 기대 모드 재처리로 성공 ✔" 를 표로 보여 준다.
- 대시보드(DMY) 실제 경로: 대상일=어제로 만들고 → 일배치 스케줄 · `POST /internal/batch/run`(로컬 검증 확인) → 관리 화면 [긴급 재처리]
  (`POST /internal/batch/reprocess {execId, stepTypeCd: COLLECT|ANALYZE|SEND}` — 원배치 T1 구간 전체를 그 단계부터. 한 구간 안의 다른 시나리오 건도
  보존물이 없으면 앞 단계로 내려가 성공한다).

### 1.6 초기화 분리

| 버튼 · API | 지우는 것 | 남기는 것 |
|---|---|---|
| [시뮬레이터 데이터 초기화] · `DELETE /api/v1/mock/sim-data?target=SIMULATOR` (**인자 없으면 이것 — 하위 호환**) | 음성 SIM 행 · 더미 원본(`mock_*`) · 이미지 SIM(보라미 · Admin 매핑 · 원본 · 저장 사진 — 이번에 추가) · 멱등 표식 · 수신 파일 · 재처리 보존물 · SIM 소진 표시 | **DMY 전부**(행 · 파일 · 멱등 표식 · 보존물) · 수행 이력 |
| [대시보드 테스트 데이터 초기화] · `DELETE …?target=DASHBOARD` | `DMY` 접두 **+ `CRT_USR_ID='dmyadm'`** 행(특이수용자 · 녹취 · 통화 · 공통파일 · 이미지) · XVARM(생성자 컬럼이 없어 **DMY 접두 + 우리 공통파일의 문서ID** 로 한정) · Admin 사진 매핑(`DMYIMG…`) · 더미 원본 · 저장 사진 · DMY 멱등 표식 · 보존물 | SIM 전부 · 수행 이력 |

- **로그 컬렉터 수행 이력(T1~T5)은 어느 쪽도 지우지 않는다**(다른 서비스 소유) — 응답 `historyKept` · 화면 팝업에 안내.
- 예전 [시뮬레이션 데이터 초기화](시험 이력 TST 까지 삭제, `DELETE /api/v1/mock/test-data`)는 시뮬레이터 초기화 확인 창의 **"시험 이력도 함께 지우기"** 체크로 남겼다.
- 로컬 산출물 정리를 `mock/LocalArtifacts` 로 뽑아 **이름으로 가른다**(`meet-DMY-…` · `decrypted_dmy_…` · `dmy_…` · `DMYIMG…`). 그래서 [시뮬레이션 데이터 생성](Clean & Seed) ·
  성능 시험 회차 준비 · 3번 탭 ④ 원클릭이 지우던 멱등 표식도 **DMY 의 것은 남는다**(실제 배치가 처리한 DMY 표식을 지우면 다음 배치가 다시 처리해 제논 · 이력이 중복된다).

### 1.7 일 단위 자동 생성 (선택 항목) — `mock/MockDataScheduler`

`unstructured.mock.daily.enabled=true` 일 때만 빈이 생긴다(기본 끔 · dev/local 전용). cron(기본 `0 30 1 * * *` 한국 시각 — 관리 화면 일배치 02:00 전)마다
**어제 날짜로 DASHBOARD 추가** → **`retain-days`(기본 7) 지난 DMY 행 · 파일 정리**(행은 `CRT_DT < 기준일`, 파일은 이름의 날짜). catch-up 없음.

## 1. 제논 직접 전송 — data-collector 와 같은 양식 (쉬운 설명)

예전: STT 결과 한 건마다 multipart(파일 + 메타데이터)로 제논에 따로 보냈다.
지금: **배치 하나 = 택배 한 묶음(전송 런)**. 건마다 상자에 담아 두었다가(쌓기) 배치가 끝나면 상자를 **번호(X-Seq) 순서대로 몇 개씩 묶어(청크)** 보낸다.

| 항목 | 값 |
|---|---|
| 주소 | `POST {zenon.base-url}{zenon.transfer-path}` — 기본 경로 `/api/v1/learn/transfer`(data-collector `transfer-path` 와 같음) |
| 본문 | `{"header":{"runId","dataTypeCd":"UNSTRUCTURED","collectDtm":"…+09:00","setTypeCd":"VOICE"},"payload":[{"managementNo":교정번호,"rawDataset":{recFileId, kind, inmatePid, srcFileName, engine, durationSec, charCount, transcript{text, language, segments}}}]}` |
| 헤더 | `X-Run-Id`(= 실행 ID) · `X-Seq`(1부터) · `X-Is-Last`(마지막 청크만 true) · `X-Target-Cnt`(런 전체 건수) · `X-Chunk-Cnt`(이 청크 건수) · `X-Data-Type` · `Content-Encoding: gzip` · `Transfer-Encoding: chunked` |
| 성공 | HTTP 2xx(응답 꼬리에 `"aborted"` 가 있으면 실패) · 중복 청크는 200 + `duplicate:true`(받은 것으로 친다) |
| 실패 | 한 청크가 실패하면 **뒤 청크는 보내지 않는다**(번호가 비면 받는 쪽이 유실로 본다). 실패 청크와 그 뒤 건은 SEND 실패 · 전사 보존(`stt_temp`) |
| 재처리 | `FROM_SEND` 재처리는 STT 없이 전사로 다시 보내는데, 원배치 런이 마감 전이면 **그 런을 다음 번호부터 이어** 보낸다(이어달리기). 어디까지 받아들여졌는지는 `{ROOT}/zenon/transfer_runs.json`(PV)에 남아 재기동해도 이어 간다 |
| MOCK(개발계 기본) | 네트워크 없이 **수집기 내장 수신기**(`ZenonMockReceiver`)로 — 본문 · 헤더는 REST 와 같고, 장부(받은 번호 · 빈 번호 · 상태) · 중복 · 헤더 누락 400 · 해제 상한 413 · 유실 판정 INGEST-GAP · 장애 흉내(전부 503 / n번부터 503)를 한다. dev · local 은 `POST /api/v1/mock/zenon/transfer` 로도 열림 |
| 키 표식(SF) | 더미의 전송 장애 표식은 보내기 **전에** 그 건만 한 번 거부(청크는 멈추지 않음) — 기존 시나리오 그대로 |

설정(`application.yml` `zenon:`): `ZENON_MODE` · `ZENON_BASE_URL` · `ZENON_TRANSFER_PATH` · `ZENON_GZIP` · `ZENON_CHUNK_RECORDS`(50) · `ZENON_MAX_PAYLOAD_BYTES`(50MB) · `ZENON_SET_TYPE_CD`(VOICE) · `ZENON_READ_TIMEOUT_MS`(60s) · 내장 수신기 `ZENON_MOCK_MAX_DECOMPRESSED_BYTES`(512MB) · `ZENON_MOCK_GAP_TIMEOUT_SEC`(60).
`tools/zenon-mock`(FastAPI)도 새 양식으로 바꿨다(장부 · 장애 · 413).

> ⚠ 제논 실제 수신 주소 · 인증 · `setTypeCd` 값은 아직 협의 전이다(개발계는 MOCK). 수집기 쪽은 설정만 바꾸면 된다.
> 이미지 SEND 는 예전처럼 **저장 + Admin DB 매핑**이다(제논 전송 대상 아님).

## 1. 쉬운 설명

전송 '봉투'(gzip · 청크 · 순번 헤더)는 10-05 에 정형 수집기와 똑같이 맞춰 두었고, 그 봉투를 받는 창구가 바로 **에이전트 커넥터의 bypass 창구**
(`/api/v1/learn/transfer` — 비식별하지 않고 그대로 제논으로 넘기는 창구)다. 그런데 우리가 그 창구를 '제논' 이라고 부르고, 설정 · 화면에도 "커넥터 없이 제논 직접"
이라고 적었다. → 이름과 주소만 '에이전트 커넥터' 로 바로잡았다. 비식별 창구(`/api/v1/deid/pipeline`)는 부르지 않으므로 단계는 그대로 3단계다.

```
[수집 COLLECT] → [정제/분석 ANALYZE · STT] → [적재/전송 SEND] ──(gzip · 청크)──▶ 에이전트 커넥터 /api/v1/learn/transfer ──(bypass)──▶ 제논
```

## 3. 주의 · PL 께 알릴 것

- **커넥터 쪽 표기 하나** — 커넥터 `LearnTransferController` 는 `X-Chunk-Cnt` 를 '전체 청크 수' 로 읽는다(주석 · 완료 판정 `received >= chunkCnt`).
  정형 수집기(`ChunkMeta.chunkCnt` = **이 청크의 레코드 수**)와 비정형은 '청크 레코드 수' 로 보낸다. 그래서 커넥터 로그가 `seq=3/2` 처럼 찍히고,
  마지막 청크 레코드 수가 받은 청크 수보다 크면(예: 50건 청크 3개) '수신 완료' 로그와 메모리 정리가 안 될 수 있다. 수신 자체(200)에는 영향 없음 — 커넥터 쪽 확인 필요.
- 커넥터 bypass 는 아직 **받은 본문을 세기만 하고 제논 중계는 TODO**(커넥터 코드 주석). 개발계를 REST 로 바꿔도 제논까지 가지는 않는다.
- 개발계 기본은 MOCK. 실연동은 `AGENT_CONNECTOR_MODE=REST`(차트 env 또는 수집기 재기동) — 사용자 결정 사항.
- 10-05 댓글에서 PL 께 "커넥터를 거치지 않고 제논 직접" 이라고 했던 내용은 이 변경으로 바로잡혔다(통합 문서 `ref/어드민_백엔드_통합인터페이스.md` 2.6 도 수정).

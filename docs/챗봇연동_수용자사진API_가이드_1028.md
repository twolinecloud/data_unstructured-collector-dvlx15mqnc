# [챗봇 연동 가이드] 수용자 사진 파일 API (2026-10-28)

비정형 수집기(이미지 수집)가 PV 에 저장한 **수용자 대표 사진**을 챗봇 백엔드가 받아 화면에 보여 주기 위한 연동 규격이다.
개발계 배포: 수집기 `2e548f8`(2026-10-28 11:56).

## 0. 한눈에

- **주소(클러스터 안)** — `http://unstructured-collector-dvlx15mqnc.data-pipeline.svc.cluster.local:8080/api/v1/image/photos/{corrNo}/file`
- **브라우저가 직접 부를 수 없다** — 서비스가 ClusterIP 이고 Ingress 가 없다. **챗봇 백엔드가 프록시로 중계**해야 한다
- **인증이 없다** — 이 수용자의 사진을 볼 권한이 있는지는 **챗봇 백엔드가 먼저 확인**한다
- **사진이 없거나(404) 장애(500 · 503 · 연결 실패)면 대체 이미지(Avatar Placeholder)** 를 보여 준다
- **캐시 헤더는 그대로 중계** — `Cache-Control: max-age=3600, private` · `ETag` · `Last-Modified` → 재요청은 304

## 1. 호출 규격

### 1-1. 요청

- 메서드: `GET` (본문 없이 있는지만 볼 때는 `HEAD`)
- 경로 변수 `corrNo` — **교정번호**(`TB_SRC_INMATE_PHOTO.CORR_NO`). 영숫자 1~20자만 받는다
  - 실데이터 형식: 숫자 18자리(예 `127040220200103500`)
  - ⚠ 수용자 **가명 ID(`inmate_pid`, `VP…`)가 아니다** — 가명 ID 를 넣으면 형식은 통과하지만 매핑이 없어 404 가 난다
- 요청 헤더: 필요한 것 없음. 조건부 요청 `If-None-Match` · `If-Modified-Since` 를 지원한다. `Accept` 는 무엇이든 사진을 준다

### 1-2. 응답

| 상태 | Content-Type | 본문 | 뜻 | 챗봇 처리 |
|---|---|---|---|---|
| 200 | `image/jpeg` (그 밖에 `image/png` · `image/gif` · `image/bmp` · `image/tiff`) | 사진 바이트 | 정상 | 그대로 스트리밍 중계 |
| 304 | — | 없음 | `If-None-Match` 가 지금 ETag 와 같다 | 304 그대로 중계 |
| 400 | `application/json` | `{"message":"교정번호 형식을 확인해 주세요."}` | 교정번호 형식 오류 | 대체 이미지 · 호출 측 버그로 로그 |
| 400 | `text/html` | 톰캣 오류 페이지 | 인코딩한 슬래시(`%2F`) · 역슬래시 · NUL 을 **톰캣이 먼저 거절** | 본문을 JSON 이라 가정하지 말 것 |
| 403 | `application/json` | `{"message":"허용되지 않은 사진 경로입니다."}` | 매핑된 저장 경로가 저장소 · 그 수용자 폴더를 벗어남(보안 차단) | 대체 이미지 · **보안 이벤트로 알림** |
| 404 | `application/json` | `{"message":"해당 수용자의 사진이 없습니다."}` | 사진 미등록 · 정리됨 · 파일 없음 | 대체 이미지(짧게 캐시) |
| 500 | `application/json` | `{"message":"사진 저장소를 읽지 못했습니다. 잠시 후 다시 시도해 주세요."}` | **PV(저장소) I/O 장애** | 대체 이미지(캐시 안 함) |
| 500 | `application/json` | `{"message":"사진 파일 형식을 확인할 수 없습니다."}` | 저장된 파일이 이미지 형식이 아님 | 대체 이미지 |
| 503 | `application/json` | `{"message":"사진 정보를 조회하지 못했습니다. 잠시 후 다시 시도해 주세요."}` | **매핑 조회(Admin DB) 장애** | 대체 이미지(캐시 안 함) |

> 저장소(PV) 장애는 **500**, DB 장애는 **503** 이다. 둘 다 "일시 장애 → 대체 이미지 · 캐시 안 함" 으로 같게 처리하면 된다.

- 200 응답 헤더: `Content-Type` · `Content-Length` · `ETag`(따옴표 포함, `"순번-수정시각-크기"`) · `Last-Modified` · `Cache-Control: max-age=3600, private` · `X-Content-Type-Options: nosniff`
- 오류 본문은 `{"message"}` 하나다. `Content-Type` 에 charset 표기가 없지만 **UTF-8** 이다(JSON 표준) — UTF-8 로 읽는다
  - Spring 5(Boot 2) 의 `RestClientResponseException.getResponseBodyAsString()` 은 charset 이 없으면 ISO-8859-1 로 읽어 한글이 깨진다 → `getResponseBodyAsString(StandardCharsets.UTF_8)` 로 읽는다
- 속도(개발계 · 포트포워드 경유): HEAD 1,177건 순차 44.8초(건당 38ms). 304 판단은 파일을 열지 않고 메타데이터로 한다

## 2. 브라우저 직접 호출이 안 되는 이유 — 챗봇 백엔드 프록시 필수

- 수집기 서비스는 **ClusterIP** 이고 Ingress 가 없다 — 클러스터 밖(사용자 브라우저)에서는 주소 자체에 닿지 않는다
- API 에 **인증이 없다** — Ingress 로 열면 누구나 수용자 사진을 받는다. **열지 말 것**
- `data-pipeline` 네임스페이스에 NetworkPolicy 가 없다 — 클러스터 안의 어느 파드든 부를 수 있다. 그래서 **사진 접근 통제(권한 확인)는 챗봇 백엔드가 맡는다**

```text
브라우저 ──(로그인 세션)──▶ 챗봇 백엔드 /…/inmates/{corrNo}/photo ──(권한 확인 후)──▶ 수집기 /api/v1/image/photos/{corrNo}/file
       ◀──── 사진 스트림 · 304 · 대체 이미지 ────┘                    ◀──── 사진 · 304 · {message} ────┘
```

## 3. 프록시 구현 권장

### 3-1. 체크리스트

1. **권한 확인 먼저** — 로그인 사용자가 이 수용자를 볼 수 있는지(교정시설 매핑 등)를 수집기 호출 **전에** 본다. `corrNo` 를 받은 그대로 넘기면 다른 기관 수용자 사진까지 열린다(IDOR)
2. **교정번호 형식 검사** — 영숫자 1~20자가 아니면 수집기를 부르지 않는다
3. **조건부 헤더만 넘긴다** — `If-None-Match` · `If-Modified-Since`. `Cookie` · `Authorization` · `Range` 는 넘기지 않는다
4. **응답 헤더를 중계** — `Content-Type` · `Content-Length` · `ETag` · `Last-Modified` · `Cache-Control` · `X-Content-Type-Options`
5. **본문은 스트리밍** — 사진 전체를 메모리에 모으지 않는다. **바이트를 바꾸지 않는다**(바꾸면 ETag 도 새로 만들어야 한다 — §5)
6. **304 는 그대로 304** — 본문 없이 ETag 와 함께
7. **타임아웃** — 연결 2초 · 응답 5초 권장. 연결 실패 · 타임아웃은 대체 이미지(롤링 배포 · 파드 재시작 중에도 브라우저에 500 을 내지 않는다)
8. **로그** — 사진 바이트를 남기지 않는다. 수용자 사진은 개인정보다

### 3-2. 클라이언트별 주의 (계약 테스트로 실측)

- **RestTemplate**
  - `getForEntity(url, byte[].class)` 는 본문 전체를 메모리에 담는다(사진 크기면 무방). 스트리밍은 `execute(url, GET, null, res -> …res.getBody()…)`
  - 404 · 500 · 503 은 `HttpStatusCodeException` 으로 온다 → `getResponseBodyAsString(UTF_8)` 를 JSON 으로 읽는다
  - 304 는 예외가 아니다 — 상태 304 · 본문 `null`
- **RestClient**(Spring 6.1+) — `exchange((req, res) -> …)` 로 상태별 분기하면 예외 없이 200 스트림 · 304 · 오류 JSON(`res.bodyTo(Map.class)`)을 다룬다
- **JDK HttpClient** — `BodyHandlers.ofInputStream()` 으로 스트리밍. 기본값은 HTTP/2 업그레이드를 시도하지만 수집기는 HTTP/1.1 로 답한다(문제없음). `.version(HTTP_1_1)` 로 두면 업그레이드 시도를 줄인다
- **WebClient**(이번에 실행하지 못함 — 수집기 레포에 spring-webflux 가 없다)
  - `bodyToMono(byte[].class)` 는 기본 버퍼 상한 **256KB**(`maxInMemorySize`)를 넘으면 `DataBufferLimitException` 이다. 개발계 사진은 2KB 지만 **운영 실사진은 넘을 수 있다** → `bodyToFlux(DataBuffer.class)` 로 흘려보내거나 상한을 올린다
  - `retrieve()` 는 4xx · 5xx 를 `WebClientResponseException` 으로 던진다 — 상태 분기는 `exchangeToMono` 가 편하다

### 3-3. 코드 예 — Spring MVC · JDK HttpClient (계약 테스트의 프록시와 같은 규칙 · 권한 확인만 더함)

```java
@GetMapping("/api/chat/inmates/{corrNo}/photo")
public ResponseEntity<Resource> photo(@PathVariable String corrNo,
                                      @RequestHeader(value = HttpHeaders.IF_NONE_MATCH, required = false) String ifNoneMatch,
                                      @RequestHeader(value = HttpHeaders.IF_MODIFIED_SINCE, required = false) String ifModifiedSince) {
    if (!corrNo.matches("[A-Za-z0-9]{1,20}")) {                                             // ① 형식 먼저
        return fallback("BAD_REQUEST", CacheControl.noStore());
    }
    if (!permission.canView(currentUser(), corrNo)) {                                         //    권한 확인(예: 교정시설 매핑)
        return fallback("FORBIDDEN", CacheControl.noStore());
    }
    HttpRequest.Builder b = HttpRequest.newBuilder(URI.create(COLLECTOR + "/api/v1/image/photos/" + corrNo + "/file"))
            .timeout(Duration.ofSeconds(5));
    if (ifNoneMatch != null) b.header(HttpHeaders.IF_NONE_MATCH, ifNoneMatch);              // ② 조건부 헤더만
    if (ifModifiedSince != null) b.header(HttpHeaders.IF_MODIFIED_SINCE, ifModifiedSince);
    HttpResponse<InputStream> r;
    try {
        r = http.send(b.build(), HttpResponse.BodyHandlers.ofInputStream());               // http: HTTP_1_1 · 연결 2초
    } catch (IOException e) {
        return fallback("UNAVAILABLE", CacheControl.noStore());                             // 연결 실패 · 타임아웃
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        return fallback("UNAVAILABLE", CacheControl.noStore());
    }
    if (r.statusCode() == 200 || r.statusCode() == 304) {
        HttpHeaders h = new HttpHeaders();                                                  // ③ 헤더 중계
        for (String n : List.of("Content-Type", "Content-Length", "ETag", "Last-Modified", "Cache-Control", "X-Content-Type-Options")) {
            r.headers().firstValue(n).ifPresent(v -> h.set(n, v));
        }
        if (r.statusCode() == 304) {
            r.body().close();
            return ResponseEntity.status(304).headers(h).build();
        }
        return ResponseEntity.ok().headers(h).body(new InputStreamResource(r.body()));      // ④ 스트리밍(바이트 그대로)
    }
    r.body().close();   // 오류 본문 {message} 는 로그용으로만 읽어도 된다(400 은 HTML 일 수 있다)
    return switch (r.statusCode()) {
        case 404 -> fallback("NOT_FOUND", CacheControl.maxAge(Duration.ofMinutes(5)).cachePrivate());
        case 400 -> fallback("BAD_REQUEST", CacheControl.noStore());
        case 403 -> fallback("FORBIDDEN", CacheControl.noStore());                                // 보안 이벤트 — 경보
        default -> fallback("UNAVAILABLE", CacheControl.noStore());                               // 500 · 503
    };
}
```

`fallback(...)` 은 대체 이미지(§4)를 `200` · `X-Photo-Fallback: {사유}` · `X-Content-Type-Options: nosniff` 로 내준다.

## 4. 대체 이미지(Avatar Placeholder) 처리

| 상황 | 수집기 응답 | 챗봇이 브라우저에 | 브라우저 캐시 |
|---|---|---|---|
| 사진 미등록 · 정리됨 | 404 | 대체 이미지 · `X-Photo-Fallback: NOT_FOUND` | `private, max-age=300`(5분) — 다음 수집 뒤 진짜 사진으로 바뀌게 짧게 |
| 저장소(PV) 장애 | 500 | 대체 이미지 · `UNAVAILABLE` | `no-store` — 복구되면 바로 진짜 사진 |
| Admin DB 장애 | 503 | 대체 이미지 · `UNAVAILABLE` | `no-store` |
| 연결 실패 · 타임아웃(배포 · 재시작) | — | 대체 이미지 · `UNAVAILABLE` | `no-store` |
| 형식 오류 · 경로 차단 | 400 · 403 | 대체 이미지 · `BAD_REQUEST` / `FORBIDDEN` | `no-store` · 서버 로그 경보(403 은 보안 이벤트) |
| 권한 없음(챗봇 판단) | 부르지 않음 | 대체 이미지 · `FORBIDDEN` 또는 403 | `no-store` |

- **권장: 백엔드가 대체 이미지를 내준다** — 채팅 메시지 안의 마크다운 이미지처럼 프런트가 오류를 잡기 어려운 곳에서도 같게 보인다
- 프런트에서만 처리하려면 백엔드는 상태 코드를 그대로 두고 `<img onerror>` 로 바꾼다(이때 404 와 장애를 구분하지 못한다)
- 대체 이미지는 정적 파일(SVG · PNG)로 두고 `X-Content-Type-Options: nosniff` 를 붙인다
- 재시도: 404 는 다시 부르지 않는다(5분 캐시). 500 · 503 · 연결 실패는 다음 화면 표시 때 자연스럽게 다시 부른다(no-store) — 백엔드에서 즉시 재시도 루프는 돌리지 않는다

## 5. 캐시 — ETag · Cache-Control 패스스루

- **그대로 중계한다**: `Cache-Control: max-age=3600, private` → 브라우저는 1시간 다시 부르지 않고, 그 뒤엔 `If-None-Match` 로 묻고 304 를 받는다(사진을 다시 내려받지 않음)
- **`private` 를 지킨다** — 수용자 사진이라 공유 캐시(역프록시 캐시 · CDN)에 두지 않는다
- ⚠ **ETag 는 그 URL(수용자) 안에서만 의미가 있다** — 서로 다른 수용자가 같은 ETag 를 가질 수 있다(순번 · 수정 시각 · 크기가 같으면 같다. 개발계에서 3명이 같은 ETag 로 실측됨). 챗봇 백엔드가 자체 캐시를 두면 **키는 반드시 교정번호(URL)** 로 한다 — ETag 만으로 찾으면 다른 사람 사진이 나간다
- **바이트를 바꾸면(리사이즈 · 재인코딩) 받은 ETag 를 쓰지 않는다** — 다른 바이트에 같은 강한 ETag 가 붙는다
- 사진은 정기 배치(매일 02:00)로 바뀐다 — 캐시 때문에 새 사진이 최대 1시간 늦게 보일 수 있다. 더 빨라야 하면 max-age 를 협의한다
- 교정시설 공용 PC 에 사진이 디스크 캐시로 남는 것이 문제라면 챗봇이 브라우저 쪽만 `no-store` 로 바꿔도 된다(이 경우 304 이점은 없다)

### 6-2. 운영 실사진에서 나올 수 있는 경우 — 브라우저 vs 서버 재처리 (실측)

| 경우 | 브라우저 `<img>`(크로미움) | 챗봇 백엔드가 Java ImageIO 로 다시 처리하면 |
|---|---|---|
| 기본 JPEG | 정상 | 정상 |
| JPEG + EXIF 회전(Orientation 6) | **정상** — 브라우저가 회전을 적용한다 | **160×120 으로 읽는다(회전 무시)** → 썸네일이 옆으로 눕는다 |
| CMYK JPEG | 정상 | 색이 틀어진다(배경 `#CED7E6` → `#E8EDF4`) · PNG 로는 저장 불가 |
| PNG · BMP | 정상 | 정상 |
| TIFF | **표시 안 됨**(크롬 · 엣지) | 읽힌다 |

- **결론 — 바이트를 그대로 중계하면 EXIF 회전 · CMYK 문제가 없다.** 서버에서 썸네일 · 리사이즈를 하려면 EXIF 회전 적용과 CMYK 처리를 하는 라이브러리를 쓴다
- 수집기는 형식 목록에 TIF 가 있어 운영에서 TIFF 가 저장될 수 있다 — 응답이 `image/tiff` 면 대체 이미지로 바꾸는 것을 권장한다(개발계 0건 · 운영에서 나오면 수집기 쪽 변환을 협의)
- EXIF 에 촬영 기기 · 일시 · 위치가 있으면 그대로 브라우저에 간다(개발계 0건). 운영 사진에 있으면 수집기 저장 단계에서 메타데이터를 지우는 것을 협의한다

---

## 7. 알아둘 한계

- 사진은 **하루 한 번(02:00 정기 배치)** 수집된다 — 신규 수용자는 다음 배치 뒤에 생긴다(그 전엔 404)
- 보라미에서 사진을 지워도 매핑이 남아 **지워진 사진이 계속 나올 수 있다**(원천에 삭제 표시가 없다 — 수동 대응, `수용자사진_파악이슈.md` 이슈 2)
- 수용자당 **대표 1장**(이미지순번 최대)만 준다 — 이력 · 측면 사진은 없다

## 8. 연동 체크리스트

- [ ] 경로 변수는 **교정번호**다(가명 ID `inmate_pid` 아님)
- [ ] 수집기 호출 전에 **권한 확인**
- [ ] 프록시 **스트리밍** · 헤더 6종 중계 · 바이트 그대로
- [ ] `If-None-Match` 전달 · **304 중계**
- [ ] 404 · 500 · 503 · 연결 실패 → **대체 이미지**(캐시 규칙 §4)
- [ ] 연결 2초 · 응답 5초 타임아웃
- [ ] 자체 캐시 키는 **교정번호**(ETag 아님)
- [ ] `image/tiff` 는 대체 이미지
- [ ] 운영 반영 전 **실사진 표본 점검**(형식 · EXIF · 크기)

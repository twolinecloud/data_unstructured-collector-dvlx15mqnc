[저희가 추정하는 원인]

  같은 라이브러리가 WAR 외부와 내부에 서로 다른 버전으로 두 벌 있고,
  외부(상위 클래스로더)가 먼저 로드되는 것으로 보입니다.

   · PDF — AI-R 코드가 PDFBox 3.x API(IOUtils.createMemoryOnlyStreamCache)를
           호출하는데, 실제로 로드된 것은 외부의 pdfbox-2.0.35 로 보입니다.
           → NoSuchMethodError

   · HWP — 외부의 poi-5.4.1 이 초기화 시 log4j-api 를 필요로 하는데,
           외부 경로에는 log4j 가 없고 log4j-api-2.17.1 은 WAR 내부에만 있습니다.
           상위 클래스로더에서는 WAR 내부 라이브러리를 볼 수 없어
           POIFSFileSystem 초기화가 실패하는 것으로 보입니다.
           → NoClassDefFoundError

  저희가 빌드 구성을 알지 못해 추정입니다. 다만 "파일이 잘못되었다" 가 아니라
  배포 구성 문제라는 점은 로그상 분명해 보입니다.

[영향]

  채팅 창 첨부 문서 비식별에서 PDF · HWP 를 쓸 수 없습니다.
  교정 업무 문서에서 두 포맷의 비중이 높아, 지원 여부가 도입 범위를 좌우합니다.
  (현재는 저희가 텍스트를 추출해 텍스트 API 로 넘기는 우회 경로로만 처리 가능합니다.)

  참고로 같은 OLE 구조를 쓰는 구형 Office(doc · xls · ppt)도 같은 이유로
  실패할 가능성이 있어 보이나, 아직 시험하지 못했습니다.

[요청]

  1) PDF · HWP 검출이 동작하도록 배포 구성 수정을 요청드립니다.
     예: /home/fasoo/lib 의 중복 라이브러리 정리, 또는 클래스로더 구성 조정,
         또는 log4j-api 를 외부 경로에 함께 배치
     (구체적인 방법은 파수 측 빌드 구성에 맞춰 판단해 주시기 바랍니다.)

  2) 수정 예정 시점을 알려주시면 POC 일정에 반영하겠습니다.

  3) 구형 Office(doc · xls · ppt) 지원 여부도 함께 확인 부탁드립니다.

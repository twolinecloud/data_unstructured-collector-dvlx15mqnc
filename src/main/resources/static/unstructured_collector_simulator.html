Swagger
시뮬레이션 데이터 — 용도별 현황 · 최근 생성 결과 · 시뮬레이터용(SIM · 시험 실행) / 대시보드·배치용(DMY · 실제 배치)
상단 [시뮬레이션 데이터 생성] 으로 만듭니다. 표식(CF·AF·SF)을 단 건은 실제 경로의 그 단계에서 한 번만 실패하고 재처리는 통과합니다 — 수집 → FULL · 정제/분석 → FROM_ANALYZE · 적재/전송 → FROM_SEND (이미지는 다시 돌리면 실패 건만 재처리). 시뮬레이터용(SIM)은 시험 실행 전용, 대시보드·배치용(DMY)은 실제 배치 전용입니다(서로 집지 않음). 초기화는 상단 [시뮬레이터 데이터 초기화] · [대시보드 테스트 데이터 초기화] — 로그 컬렉터 수행 이력(T1~T5)은 남습니다.
아직 이 화면에서 만든 데이터가 없습니다.
시스템 아키텍처 및 데이터 흐름 개요 — 원본 음성이 제논(Zenon)으로 넘어가기까지 · 수집 → 정제/분석 → 적재/전송 3단계와 실제 폴더
경로는 아래 디렉터리 의 현재 설정값을 그대로 보여 줍니다 — ROOT_DIR 을 바꾸면 이 그림도 같이 바뀝니다. 접견(MEET)과 전화(PHONE)는 ② 까지 경로가 다릅니다 — 전화는 XVARM 브로커를 타지 않습니다.

디렉터리
ROOT_DIR
ROOT_DIR 은 OS 로 자동 감지 — Windows C:/k8s/unstructured_collector, Linux/K8s /k8s/unstructured_collector. 표준 배치: xvram/original_voice_files · esb/meet · esb/phone · xvram/decoding (없으면 자동 생성). STT 결과는 PV 에 남기지 않고 제논(Zenon)으로 보냅니다 — 옛 xenon/ 폴더는 쓰지 않습니다(2026-10-01). ESB 수신(접견) 폴더는 로컬 브로커의 BROKER_OUTPUT_DIR 과 같아야 합니다 — [브로커 연결 확인] 으로 대조.
연동 상태 — DB · 브로커 · 로그 컬렉터 배치를 돌리기 전에 여기서 먼저 대조하십시오
두 경로가 어긋나면 브로커는 "추출 완료" 를 돌려주는데 수집기는 빈 폴더를 봅니다

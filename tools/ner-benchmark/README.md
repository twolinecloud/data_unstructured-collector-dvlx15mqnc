# 한국어 PII NER 벤치마크 — AI-R · 제로샷 · 도메인 튜닝

정규식 · 형태소 분석기(가름 등)를 섞지 않은 **순수 딥러닝 NER** 끼리 비교하는 도구다.
파일 하나(`ner_benchmark.py`)에 데이터 생성 · 학습 · 추론 · 채점 · 리포트가 다 들어 있다.

| 줄 | 모델 | 무엇 |
|---|---|---|
| ① | **AI-R** | 파수 AI-R 결과 JSON 을 주입받아 채점. `labelResult`(딥러닝)만 쓴 줄과 `patternResult`(정규식)까지 합친 '제품 전체' 줄을 따로 낸다 |
| ② | **제로샷** | `monologg/koelectra-base-v3-naver-ner` 를 그대로(추가 학습 없음) |
| ③ | **도메인 튜닝** | 같은 몸통 `monologg/koelectra-base-v3-discriminator` 를 교정 도메인 합성셋으로 3~5 에포크 `Trainer` 학습 |

②와 ③은 몸통 · 토크나이저가 같다. 둘의 점수 차이는 **도메인 튜닝을 했느냐** 하나에서 나온다.

## 설치

```bash
pip install "torch>=2.6" "transformers>=4.46" "datasets>=3.0" seqeval accelerate
```

검증한 조합은 Python 3.13 · torch 2.14.0(CPU) · transformers 5.17.0 · datasets 5.0.1 · seqeval 1.2.2 · accelerate 1.15.0 이다.
GPU 는 없어도 된다. 모델 두 개(각 약 450MB)는 처음 실행할 때 `~/.cache/huggingface` 에 받는다.

> **Windows 경로 길이** — torch 는 깊은 헤더 파일을 깐다. 가상환경을 긴 경로(사용자 임시 폴더 아래 등)에 만들면
> 260자 제한에 걸려 설치가 깨진다. 이 폴더 안 `.venv`(gitignore 됨)처럼 짧은 경로에 만든다.

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install torch==2.14.0 transformers==5.17.0 datasets==5.0.1 seqeval==1.2.2 accelerate==1.15.0
```

## 실행

```bash
python ner_benchmark.py run --quick
```

| 명령 | 하는 일 |
|---|---|
| `run` | 데이터 생성 → ② 제로샷 → ③ 튜닝 → 채점 → `out/REPORT.md` · `out/results.json` |
| `run --quick` | 학습 200문장/트랙 · 3 에포크 — CPU 로 파이프라인만 빨리 확인 |
| `run --train-tracks AB` | 일반 문맥(A)까지 같이 학습. 요구사항 기본은 B(교정)만이다 |
| `run --air-json <파일>` | AI-R 결과를 주입해 3자 비교 |
| `gen` | 데이터셋만 — `out/data/*.jsonl` + HF `DatasetDict`(`out/data/hf`, `load_from_disk` 로 읽힘) |
| `export-air` | AI-R 에 넣을 시험 40문장 — `out/air_input.jsonl` |
| `air-fetch` | 커넥터로 AI-R 결과를 받아 `out/air_result.json` 에 그대로 저장 |
| `air-oracle` | 정답을 AI-R 응답 모양으로 바꾼 **자가검증** 파일. 실제 AI-R 결과가 아니다 |

같은 설정 · 같은 학습셋이면 학습한 모델(`out/ft_model_<트랙>`)을 다시 쓴다. 새로 학습하려면 `--retrain` 을 준다.
`--tag <이름>` 을 주면 리포트가 `out/REPORT_<이름>.md` 로 남아 실행끼리 덮어쓰지 않는다.

CPU(14스레드) 실측 — 학습 200문장 × 3 에포크 70초, 600문장 × 4 에포크 약 4~5분. 시험 40문장 추론은 모델당 1초 안팎이다.

## 데이터

라벨은 `O · B-PER · I-PER · B-NUM · I-NUM · B-LOC · I-LOC` 이고 **어절(공백) 단위 BIO** 다. 제로샷 모델(Naver NER)이 학습한 단위와 같다.
조사가 붙은 어절(`김다정의`)은 그 어절 전체가 개체다.

| | Track A 범용 | Track B 교정 |
|---|---|---|
| 시험(봉인) | 20문장 · 정답 36개(이름 · 전화 · 주민 · 계좌 · 주소) | 20문장 · 정답 43개(수용자명 · 수용번호 · 접견번호 · 사건번호 · 전화 · 주민 · 주소) |
| 학습(생성) | 업무 · 고객응대 · 메신저 템플릿 35 + 개체 없는 문장 11 | 접견 녹취(STT) · 상담일지 · 공문 템플릿 38 + 개체 없는 문장 13 |

**시험셋은 봉인 세트다.**
- 손으로 써서 고정했다. 학습셋은 다른 템플릿 · 다른 값 풀에서 만든다.
- 시험셋의 이름 전체와 **이름 부분**(다정 · 소망 · 하늘 …)은 학습 생성에서 뺀다. 그래서 시험의 모든 이름은 모델이 처음 보는 이름이다.
- 실행할 때마다 겹침을 세어 리포트 머리에 적는다(문장 · 이름 · 번호 · 주소 모두 0 이어야 정상).
- 시험셋을 보고 학습 · 설정을 고치면 그 숫자는 오염된다. 고칠 때는 새 id 로 새 세트를 만들고 첫 실행을 다시 남긴다.

시험셋은 비식별 실측(문서비식별 1~5단계 · 가름 v1~v17)에서 엔진들이 놓친 자리로 채웠다.

| 함정 | 시험 예 |
|---|---|
| 낱말과 같은 이름 · 같은 문장 속 동형이의어 | `정미소 씨가 … 동네 정미소에` · `최강산` · `한소망` · `박하늘` |
| 외자 · 희성 · 복성 | `임별` · `주진` · `국란` · `평광호` · `판석규` · `어겨울` · `제갈민규` · `서문혁` |
| 문맥 없는 나열 · 이름만 | `명단: 변하람, 심겨레, 주아람, 태도현` · `나야 나 민수` |
| STT 가 쪼갠 이름 | `김도 윤 씨` |
| 말로 부른 번호 · 띄어 쓴 번호 | `공일공 칠삼사이 팔팔일오` · `010 5520 1847` |
| 하이픈 없는 주민번호(체크섬 맞춤) | `9708251083422` |
| 접미사 없는 건물명 | `판교역로 166 에이치스퀘어 N동` |
| PII 아닌 숫자 · 이름 같은 낱말(과탐 시험) | `오전 10시, 3번 출구, 총 5명` · `수용동 3동 12실` · `하늘도 맑더라` |

## AI-R 결과 넣기

1. `python ner_benchmark.py export-air` 로 시험 40문장(`id` · `text`)을 받는다.
   `text` 는 **한 글자도 바꾸지 말고** 보낸다. `start`/`end` 가 그 문자열 기준이다.
2. AI-R 응답을 아래 셋 중 한 모양으로 모아 `--air-json` 으로 넘긴다. JSON 객체(id 가 키)도 되고 JSONL(줄마다 `id`)도 된다.

```jsonc
// (가) AI-R 응답 그대로 — 커넥터 /api/v1/deid/air/detect 응답이나 detectResult 를 id 별로
{ "_meta": {"label_option": "aa9c319e…", "pattern_option": "7544fa7c…", "source": "…/air/detect?server=test"},
  "A01": { "labelResult":   [[{"except": false, "entity": "SS_NAME", "word": "김다정", "start": 7, "end": 10, "order": "B"}]],
           "patternResult": [[{"except": false, "pattern": "a3e59e06…", "word": "010-4821-7735", "start": 29, "end": 42}]] } }

// (나) 단순 구간
{ "A01": {"entities": [{"label": "PER", "start": 6, "end": 9}]} }

// (다) 어절 BIO 를 직접
{ "A01": {"tags": ["O", "B-PER", "O", "O", "O", "O", "B-NUM", "O", "O"]} }
```

채점 규칙(커넥터 측정 하네스와 같다):

| 규칙 | 이유 |
|---|---|
| `SS_NAME`→PER · `AD_*`→LOC · `patternResult`→NUM · `ORG_*` · `*_BRAND`→O | 이번 범위는 이름 · 번호 · 주소다 |
| 붙어 있는 주소 조각은 하나로 합친다(**모든 모델 공통**) | AI-R 은 주소 하나를 6~7조각으로, Naver NER 은 지명마다 따로 단다 — 관례 차이라 안 합치면 부당하게 불리하다(`AirProbe` 와 같은 보정). 건물번호를 NUM 으로 다는 관례는 보정하지 않는다 |
| 정규식과 딥러닝이 같은 자리를 다르게 달면 정규식 유형을 따른다(제품 전체 줄) | AI-R 이 전화 `051-744-2310` 을 정규식(전화)과 딥러닝(주소)으로 동시에 달았다. AI-R 에 유리한 쪽의 보정이다 |
| `word` 가 원문 `text[start:end]` 와 다르면 버리고 센다 | 좌표가 어긋난 것을 조용히 받으면 엉뚱한 자리가 채점된다 |
| 교정 식별번호를 뺀 **공통 범위** 점수를 따로 낸다(2-B절) | AI-R 프로파일에 수용 · 접견 · 사건번호 패턴이 없다 — '설정에 없다' 를 '못 잡는다' 로 세지 않는다(3계층 비교 §2.1) |
| `except: true` 는 개체가 아니다 | 예외 단어(마스킹 제외) |
| `"_meta": {"mock": true}` 면 리포트 맨 위에 **모의 입력** 경고 | 모의 숫자가 AI-R 성능으로 읽히지 않게 |

> AI-R 은 사람 이름을 `ORG_BIZ` 로 단 적이 있다(가름 인수인계 7-4). 그런 개체는 strict F1 에서는 놓침이지만,
> **남은 개인정보**(유형 무관) 열에서는 막은 것으로 센다. 두 열을 같이 본다.

- 조직 전체 프로파일(테스트 서버): 딥러닝 `aa9c319e2ef84ab9b750c074f6b3feca` · 정규식 `7544fa7c994d46c09c8bffd88995b924`(커넥터 `application.yml` 주석 · `sim_presets.py`).

## 리포트 읽는 법

| 절 | 내용 |
|---|---|
| 1 | 3자 비교 매트릭스 — Track A · B 의 strict 개체 F1 과 부트스트랩 95% 구간, B − A |
| 2 | 개선 폭 — **도메인 튜닝 − 제로샷**(도메인 적응 효과) · 튜닝 − AI-R · 제로샷 − AI-R. 같은 표본으로 잰 차이의 95% 구간 |
| 2-B | 공통 범위 — 교정 식별번호를 뺀 F1 과 차이(AI-R 프로파일이 다루는 유형만) |
| 3 | 트랙별 P · R · F1, 유형별 F1, **남은 개인정보**(한 어절이라도 안 가린 개체) · 어절 가림률 · 과탐률 |
| 3-C | 번호 세부 — 전화(말로 부른 번호 포함) · 주민 · 계좌 · 교정 식별번호별 찾음 · 가림 |
| 4 | CPU 추론 속도 |
| 5 | 모델별 틀린 자리(놓침 · 과탐) |
| 6 | 숫자를 믿기 전에 알아야 할 것 |

20문장 세트라 구간이 넓다. **구간이 겹치는 차이는 이 세트만으로 단정하지 않는다.**
개선 폭은 2절의 대응 부트스트랩 구간이 0 을 넘지 않을 때만 '확인됨' 으로 읽는다.

  말로 부른 번호 · 띄어 쓴 번호. Track A 는 낱말 같은 이름 · 외자(정미소 · 한소망 · 채다움 · 임별 · 심겨레) · 띄어 쓴 번호.
  하이픈 없는 주민번호는 조직 전체 프로파일이 잡았다.
- 개발계 기본 프로파일(스모크테스트용)로 받은 AI-R 은 제품 전체 77.6 · 72.2 — 프로파일에 따라 숫자가 움직인다(`REPORT_*_air_dev_default.md`).

- 튜닝 모델의 남은 오류는 대부분 **주소 끝 경계**다(`… N동 1층` · `대학로 99 관리실에` 까지 잡음). 개인정보는 가려지지만 strict 에서는 틀린다.
  B만 학습한 모델은 `강산이`(낱말)를 이름으로 잡았고, A+B 학습에서 없어졌다.
- **AI-R 형식 자가검증**(`air-oracle`) — 제품 전체 모드 100.0 · 100.0. 형식 파싱 · 라벨 매핑 · 주소 조각 합치기가 맞다.

## 한계

- 합성 데이터다. 실제 접견 녹취 · 상담일지는 오타 · 사투리 · 잡음이 더 많다. 실데이터가 오면 그 분포로 새 봉인 세트를 만들어 다시 잰다.
- 시험 이름은 학습에 없지만, 문장 틀은 같은 사람이 같은 도메인 감으로 썼다. 도메인 튜닝 숫자는 '합성 분포 안의 일반화' 로 읽는다.
- 어절 단위 채점이라 글자 단위 경계(조사 떼기)는 재지 않는다. 가명 치환에 쓰려면 글자 단위 경계가 따로 필요하다.
- 제로샷 모델의 범위 밖 라벨(ORG · DAT · TIM …)은 O 로 맞췄다. 제로샷 NUM 은 수량 전반을 잡도록 학습돼 과탐이 생긴다 — 모델의 성질이다.

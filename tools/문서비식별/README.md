# 문서 비식별 시험 도구

| 파일 | 쓰임 |
|---|---|
| `gen_docs.py` | docx · xlsx · pptx 시험 문서 + 정답표 생성. `python gen_docs.py <출력폴더>` |
| `hwp_convert.ps1` | 그 docx 를 **hwp · hwpx · pdf** 로 변환. 한글이 깔린 PC 에서만 된다 |
| `verify_docs.py` | 생성한 문서에 정답 PII 가 실제로 들어갔는지 확인 |
| `score.py` | AI-R 응답을 채점해 `REPORT.md` 생성 |
| `rrn_test.py` | 주민번호 꼴별로 패턴이 걸리는지 확인(체크섬 · 하이픈) |

## 왜 두 갈래인가

**hwp · hwpx 는 클러스터에서 만들 수 없다.** 한글 COM(`HWPFrame.HwpObject`)이 필요하고
그건 한글이 깔린 PC 에만 있다. 그래서 그 두 포맷은 여기서 미리 만들어 레포에 담아 두고,
docx · xlsx · pptx 는 조건(장수 · 표 유형 · PII)별로 그때그때 생성한다.

PDF 도 한글 내보내기로 만든다 — 이 PC 에 Word 는 없다(ProgID 만 남아 있고 클래스 미등록).

## 함정 둘 (둘 다 한 번 걸렸다)

1. **주민번호는 체크섬을 검사한다.** 체크섬 안 맞는 가상 번호를 쓰면 영원히 미탐으로
   보이고 "AI-R 이 주민번호를 못 잡는다" 는 틀린 결론이 나간다. `gen_docs.py` 가
   체크섬을 계산해 넣는다 — 그 로직을 지우지 말 것.
2. **openpyxl 은 한글을 XML 수치참조로 쓴다**(`홍길동` → `&#54861;…`). 채점기가
   엔티티를 안 풀면 "PII 누락" 으로 잘못 읽는다. `verify_docs.py` 는 `html.unescape` 한다.

## 채점은 출현 횟수로

자리별 O/X 를 전체 텍스트 검색으로 만들면 안 된다 — 한 군데만 남아도 그 값의 모든
자리가 X 가 된다(처음에 그렇게 찍혀서 5자리 전부 미가림으로 읽었다. 실제로는 5회 중 2회).
`score.py` 는 **값별 출현 횟수**와 **파트별**로 센다.
